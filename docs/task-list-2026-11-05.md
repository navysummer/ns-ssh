### K07 验证证据
- 单元测试：`sntrup_hybrid_round_trip_agrees_on_shared_secret`（共享密钥一致、长度校验）。
- 集成测试：`sntrup_hybrid_kex_round_trip`（自有客户端↔自有服务端，强制 sntrup，`SNTRUP_KEX_OK`）。
- 真实 OpenSSH 服务端（只通告 `sntrup761x25519-sha512`）：客户端完成 KEX+NEWKEYS（sshd 日志 `kex: algorithm: sntrup761x25519-sha512`）。
- 真实 OpenSSH 客户端（`ssh -o KexAlgorithms=sntrup761x25519-sha512`）↔ 自有服务端：`REAL_SSH_SNTRUP_OK`。

### M03 验证证据
- 单元测试：`umac_matches_openssh_reference_vector`（对 OpenSSH `umac.c` 用 C 参考编译出的真实向量：短 32B 走 L1/L3，长 2048B 走 L2/L3；`umac-64`→`4a1fbc94ce158caa`/`1e009bb01be8c4ff`，`umac-128`→`f3afd5f31f9e6e86bafaa8d2a42a6887`/`a7b0f2d7ca6326d3954354f99df197ab`，均一致）。
- `verify_tag_accepts_exact_tag_and_rejects_any_mutation` 已扩展覆盖 UMAC 变体（数据/序号/翻转任一位均拒绝）。
- 默认 MAC 列表 `DEFAULT_MACS` 与 OpenSSH 9.9 客户端默认完全一致（含 `umac-*-etm` 前四位之一）。
- 依赖：新增 `aes`/`cipher`/`generic-array`（均已在锁文件，纯 Rust）。

## P3（边缘/旧协议）

### 3.1 C07 `none` cipher
- **现状**：✅ 已完成（2026-11-05）。`NoneCipher`（identity、key/iv=0、block=8）接入 `create_cipher`;`filter_algos` 显式列表接受 `none`(默认列表仍不含),`install_new_keys` 以零长 key/iv 安装。`none` 仅显式配置生效,默认提案从不通告。
- **验证**：`none_cipher_is_identity` 与 `none_cipher_is_negotiable_only_when_explicitly_configured` 单元测试;ns-ssh 客户端↔ns-ssh-server 双向 `Ciphers=none`+`MACs=none` 命令执行 `EXIT=0`。

### 3.2 M04 hmac-md5/ripemd160
- **现状**：✅ 已完成（2026-11-05）。`hmac-md5`、`hmac-md5-96`、`hmac-md5-etm@openssh.com`、`hmac-md5-96-etm@openssh.com` 接入 `create_mac`/`get_supported_macs`;`filter_algos` 新增 `supported` 集,显式 `MACs` 可选中默认禁用算法。`hmac-ripemd160` 在 OpenSSH 9.9 已移除,不实现。
- **验证**：`verify_tag_accepts_exact_tag_and_rejects_any_mutation`(含 MD5 变体)与 `hmac_md5_matches_rfc2202_vector` 单元测试;ns-ssh 客户端↔ns-ssh-server 双向 `MACs=hmac-md5` 命令执行 `EXIT=0`;`-Q mac` 默认提案与 OpenSSH 一致(不含 MD5/none)。

### 3.3 P11 first_kex_packet_follows
- **现状**：✅ 已完成（2026-11-05）。`negotiate_algorithms` 解析 `first_kex_packet_follows` 标志并计算 `*_wrong_guess`;客户端/服务端在初始握手与 rekey 路径收到对方 KEXINIT 后,若猜测不中则丢弃对方的下一 KEX 包(RFC 4253 §7)。发送侧仍恒置 0(与 OpenSSH 一致,从不猜测)。
- **验证**：`first_kex_follows_wrong_guess_is_detected` 单元测试;双向互通(OpenSSH 客户端↔ns-ssh-server、ns-ssh 客户端↔OpenSSH server)均 `EXIT=0`。

### 3.4 R02 scp `-p`
- **现状**：✅ 部分完成（2026-11-05 复核）。`-p` 已识别；`scp.rs` 恒用远端 `scp -t/-f -p` 并发送 T 头，mode/mtime 已保留。atime/owner 保留需远端协议配合（T 头仅带 mtime），属边缘缺口。
- **验证**：`scp -p` 后 `stat` 对比（mode/mtime 一致）。

### 3.5 R04 scp 多源/远程到远程
- **现状**：✅ 已完成（2026-11-05）。`scp_upload_multi`/`scp_download_multi` 支持单会话多源；`run_scp_mode` 按"末位即目标"重排，修复第二远端源被误判为目标；下载侧剥离 `user@host:` 前缀并以缓冲行读处理 `T`+`C` 合包。remote→remote 仍不支持（OpenSSH 亦需经本机中转）。
- **验证**：`scp_multisource_upload` 与 `scp_multisource_download` 集成测试通过。

### 3.6 X03 X11 trusted（-Y）
- **现状**：✅ 已完成（2026-11-05）。`-Y` 置 `forward_x11_trusted`；`register_x11_cookie` 对 `-X` 用 `xauth untrusted`，对 `-Y` 用 trusted 条目。
- **验证**：`x11_forwarding_round_trip` 集成测试通过。

### 3.7 X04 X11 MIT-MAGIC-COOKIE 写入
- **现状**：✅ 已完成（2026-11-05）。默认 `XAuthLocation=/usr/bin/xauth`（`_PATH_XAUTH`），`-X`/`-Y` 自动写 `~/.Xauthority`。
- **验证**：`x11_forwarding_round_trip` 集成测试通过。
